# HDMI + gray DMA source snapshot

`rebuild_hdmi_bd.tcl` is the captured Vivado 2025.2 BD Tcl for the HDMI + gray DMA design; `rebuild_hdmi_project.tcl` creates a separate project, generates the BD and wrapper, adds XDC, and runs Validate Design. A smoke rebuild completed that stage. **The smoke run did not perform a fresh synthesis, implementation, bit comparison or board test.** The original implementation produced `HDMI_CANDIDATE.bit/.hwh/.xsa`, and A later demonstrated 800×600 HDMI plus grayscale DMA using that candidate. The already public binaries should remain in their existing repository location; do not replace them from this source snapshot without a new validation cycle.

The source archive requires the `axi_dynclk_v1_0` IP under `hdmi_reference/`. It is deliberately omitted from this public tree because the local copy includes a Xilinx `mmcme2_drp.v` with an all-rights-reserved notice and its redistribution basis has not been established. Obtain the matching vendor/Digilent source separately; see `DYNAMIC_CLOCK_SOURCE.md` for provenance and exact hashes. Until that dependency is supplied, the Tcl **cannot** complete a standalone rebuild. AMD catalog IP (VDMA, VTC, AXI4-Stream to Video Out, PS7, interconnect) is generated by Vivado.

The gray DMA remains `axi_dma_0` at `0x40400000`. Display IP is `axi_vdma_0` at `0x43000000`, `v_tc_0` at `0x43C00000`, `axi_dynclk_0` at `0x43C10000`, and `hdmi_reset_gpio` at `0x41200000`. VDMA reads RGB888 frames from DDR via HP0; the video stream uses frame-start `TUSER` and **line-end** `TLAST`, separate from the grayscale IP's whole-frame `TLAST`. Control is via GP0. See `reference/HDMI_IP参数与AXI地址映射.md` for parameters.

The static XDC here constrains a 1280×720 74.25 MHz candidate clock. A's successful HDMI display used **800×600, 40 MHz programmed at runtime**. The board result does not prove a new 720p mode or every static delay assumption. Verify clocking, display mode, IO bank voltage and reset on the target hardware before changing timing/bitstream.
